# 成长引擎 v2：按学习阶段长大（2026-11-03 定稿）

> 用户推翻 v1：
> 「成长绝对不能靠真实时间，事件全部按照真实时间，还有就是主动性也要按真实时间，
> 成长就按学习阶段来，按照人的小学、初中、高中、大学、工作的阶段，学习到哪，成长到哪」
>
> v1 文档（`growth-2026-11-03.md`）里的"年龄曲线 / aging_rate"已作废，只留作历史。

## 1. 三条时间分工（这一版最重要的一张表）

| 维度 | 依据 | 实现 |
|---|---|---|
| **成长阶段**（小学→初中→高中→大学→工作） | **学习量（学分 xp）**，与时钟无关 | `aiji/brain/growth.py::Growth.sync()` |
| **事件时间**（对话、生命事件、会话起止） | **真实时间**（`time.time()`，epoch 秒） | `turn.ts` / `being_event.at` / `heart_state` |
| **主动性节奏**（静默阈值、冷却、24h 额度） | **真实时间**（秒/天） | `aiji/endocrine/proactive.py`、`life_loop.py` |

守卫：`tests/test_growth.py::RealTimeIsForEventsAndProactivityTest` 直接读源码断言
`proactive.py` / `life_loop.py` **不出现** `growth`/`age_years`，且必须用 `time.time()`。
另有一条反证用例：`test_age_comes_from_stage_not_calendar`——同一份数据把注入时钟
往后拉一年，阶段/年龄/xp 一个字都不许变。

## 2. 学分从哪来（只结算增量，幂等）

| 学习证据 | 权重 | 为什么算"学到" |
|---|---|---|
| 新事实 `fact` | 1.0 / 条 | 学到一条可复用的知识 |
| 新反思 `reflection` | 2.0 / 次 | 把这段对话想明白了 |
| 新性格 `trait` | 5.0 / 条 | 沉淀成稳定习惯（最值钱） |
| 新会话 `session` | 3.0 / 个 | 跟一个新的人/一段新关系相处过 |
| 对话轮次 `turn` | 1.0 / 10 轮 | 练手 |
| 爬到的帖子/文档 `learn` | 2.0 / 篇 | 自己主动去读的东西 |

门槛（`scale=1.0` 时）：小学 0 → 初中 **1200** → 高中 **4000** → 大学 **9000** → 工作 **16000**。
`scale` 一个数整体缩放（>1 长得更慢），存在 `growth.json` 里，`aiji grow --scale 2` 可调。

一个正常活跃日（50 条事实 + 500 轮 + 5 个新会话 + 10 次反思 + 10 篇帖子）≈ 155 学分
→ 大约 8 天到初中、26 天到高中、58 天到大学、103 天到工作。真正卡住成长的是"没东西学"，
而不是"时间没到"。

```json
{
  "schema": 2,
  "born_at": 1793672911.8,        // 真实时间，仅用于显示"从哪天开始长"
  "xp": 0.0,
  "scale": 1.0,
  "baseline": {"fact": 21431, "reflection": 1850, "trait": 0,
               "session": 735, "turn": 24966, "learn": 274},
  "db_path": "D:\\AIJiYi\\data\\aiji.db",
  "stage": "primary", "stage_since": 1793682000.0,
  "milestones": [], "last_sync": 1793682000.0
}
```

- **没有** `rate` / `start_age`：v1 的"每个真实天 = 30 角色天"被彻底删掉，
  `test_no_rate_or_birthdriven_math_left` 断言这两个常量/字段不存在。
- `baseline` = 上次结算时的计数快照；`sync()` 只把 `当前 - baseline` 换成学分，
  所以跑一百次也不重复计（`test_sync_is_idempotent`）。
- 学分**只增不减**：数据被清理也不会退分（`test_sync_never_goes_backwards`）。
- 年龄（`age_years()`）= 当前阶段区间内按阶段进度插值，只用于提示词文案，
  `describe()` 里写死 `"age_source": "learning"`、`"time_based_growth": false`。

## 4. 账本必须跟着自己的库走（真实踩过的坑）

第一版切换时，跑一次全量测试就把人送进了"工作"阶段：测试用临时库建 Memory，
`head.py` 每轮都会 `sync(memory.db)`，而账本路径是写死的 `data/persona/growth.json`
→ 临时库（1 条事实）覆盖了生产账本的基线 → 生产库一结算，两万多条历史存量全被算成
"这次学到的"，xp 直接 29837.7。

修法（三层）：
1. 没显式给路径时，账本落在**库的同级目录**：`<db 的目录>/persona/growth.json`
   （生产就是 `data/persona/growth.json`，临时库就是 `.tmp/<case>/persona/growth.json`）；
2. 账本里记 `db_path`，**换库来结算一律不动账**（`test_ledger_lives_next_to_its_db`）；
3. `bind_path()` 把"这一轮解析到的账本"共享给 `persona.style_block()`，
   避免"head 说初中、文案说小学"（`test_prompt_side_sees_the_same_ledger`）。

验收证据：全量 546 用例跑完，生产账本 `xp` 前后都是 **0.0**（跑前跑后各读一次文件）。

## 6. 接口与开关

- `GET /api/growth`：`xp / stage / progress / need_for_next / age / milestones / stages`,
  每次调用会 `sync(force=True)` 结算一次。
- `aiji grow [--set-stage primary|middle|high|university|work] [--scale N]`：
  看状态 + 演示用钉阶段 + 调门槛。
- 配置/环境：`persona_stage`（`AIJI_PERSONA_STAGE`）把阶段钉住；`persona_age`
  （`AIJI_PERSONA_AGE`）按年龄落到阶段，兼容旧脚本。**`aging_rate` 已删除。**
- 控制台 ③ 大脑「成长状态」面板 + 6 个按钮（钉到各级 / 恢复按学习进度）。

## 7. 已知边界

1. 学分是**单账本**（整个部署一个人格），多身份各自成长还不支持；
2. 最后一级 `work` 没有下一级，`progress` 恒为 1.0；
3. 学分的"质"没有区分：一条错误事实和一条正确事实一样值 1 分（要靠反思/清理去纠偏）；
4. `scale` 只能整体调，不能给单个权重调（真要调就改 `WEIGHTS`，属于产品决策）；
5. 升段那一刻写一条 `being_event`（真实时间），但**不自动改库里的 trait**
   ——写侧护栏（`reflect._ADULT_TONE_MARKERS`）仍然拒收成年语感。
