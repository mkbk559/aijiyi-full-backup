# 产品现实核对：这些功能人类到底怎么用

> 2026-10-30。用户问：“你做的这些功能人类怎么使用，有没有用，有没有更好用的开源项目？”
> 这不是功能清单，是**产品审判**。结论先放：**大部分 UI 是给开发者看的，不是给人每天用的；真正有价值的只有“记忆 + 人格 + 一个人类本来就在的入口”。**

## 1. 人类实际会怎么用

| 场景 | 人类真实行为 | 现在这套支持得怎么样 |
|---|---|---|
| 每天 | 在 QQ/微信里 @ 它，或点桌面上的鱼说话 | QQ 未跑通；桌宠能聊，但 SAPI 声音像 2005 年 |
| 偶尔 | 想让它记住一件事、问“你还记得吗” | 记忆能存/能召回，但**没有“记忆命中”的可见反馈**，用户不知道它记住了没 |
| 几乎不会 | 打开 `127.0.0.1:8787` 控制台，点 15 个页签 | 控制台是调试台，不是日用品 |
| 永远不会 | 在控制台里用文件树/终端干活 | 有 VS Code/DSH，没人会来这里写代码 |
| 一次性 | 配置模型、QQ、声音 | 配置分散在 env/文件/控制台，没有向导 |

**一句话**：人类只会用“QQ 里的它”和“桌面上的它”；控制台只在出问题时打开。

## 2. 功能有用性评级（按“人会不会用”而不是“能不能跑”）

| 功能 | 人类用途 | 评级 | 建议 |
|---|---|---|---|
| 记忆内核（事实/画像/注入） | 让它记得你 | ★★★★★（但未证明“记得有用”） | 保留，补“记忆命中反馈/评测” |
| OpenAI 兼容网关 | 让现有客户端接进来 | ★★★★★ | 保留，这是最低成本的复用 |
| QQ/IM 接入 | 在人类本来就在的地方出现 | ★★★★★ | 优先做，但别自己造框架 |
| 桌宠（形象/摸头/喂食） | 情感连接 | ★★★★ | 保留；声音是短板 |
| 主动消息 | “它想起我了” | ★★★★（现在死代码） | 接线，先一天一条 |
| 语音对话 | 免手操作/陪伴 | ★★★（SAPI 音质拖累） | 换 Edge/Piper，别做克隆 |
| 控制台仪表盘 | 看状态/排错 | ★★（开发者） | 砍到 4 个页签 |
| 记忆星图 | 演示/调试 | ★（好看，低日常价值） | 降级为表格/可选 |
| 工作区（文件/终端） | 开发者 | ☆（负价值：安全+重复） | **删/隐藏** |
| 控制台桌宠 | 和桌面桌宠重复 | ☆ | 删 |
| 语音定制 UI | 换音色 | ★★（音质不行时是口红） | 先换引擎再谈 UI |
| 审批/工具 | 让 AI 动手 | ★★★（对 agent 有用，对陪伴低） | 保留但别当卖点 |
| 内分泌/生命卡 | 人格连续性 | ★★（用户感知弱） | 保留在后台，别做页面 |

**核心判断**：功能数量 ≠ 有用。每多一个页面，就多一份维护、安全面和“用户不知道点哪”的负担。

## 3. 更好用的开源项目（2026-10-30 查）

### 3.1 QQ/IM 机器人——**别自己造框架**

| 项目 | 为什么比我们强 | License / Stars |
|---|---|---|
| [AstrBot](https://github.com/AstrBotDevs/AstrBot) | 多 IM（QQ/Telegram/Discord…）、WebUI、插件、LLM 接入、MCP，开箱即用 | AGPL-3.0 / 45.0k |
| [LangBot](https://github.com/langbot-app/LangBot) | 生产级多平台 IM Bot、知识库、插件、Dify/n8n/Coze 集成 | Apache-2.0 / 18.6k |
| [NoneBot2](https://github.com/nonebot/nonebot2) | Python 异步 Bot 框架，OneBot/QQ 适配器生态最成熟 | MIT / 7.8k |

我们手写的 OneBot 桥只覆盖了它们 5% 的能力（无重连、无限流、无媒体、无插件、无 WebUI）。
**更合理的做法**：AIJiYi 只做“记忆/人格 provider”，接进 AstrBot/LangBot 的 LLM 插件，或给 NoneBot2 写一个 50 行的 matcher。

### 3.2 聊天 UI——**别自己做控制台聊天**

| 项目 | 用途 | License / Stars |
|---|---|---|
| [Open WebUI](https://github.com/open-webui/open-webui) | 通用 LLM Web UI、知识库、工具/MCP | 自定义许可 / 157k |
| [LobeHub](https://github.com/lobehub/lobehub) | Agent 工作台/多模型/插件 | 自定义许可 / 83.6k |
| [Chatbox](https://github.com/Bin-Huang/chatbox) | 桌面聊天客户端，支持自定义 OpenAI 地址 | GPL-3.0（需确认） |

AIJiYi 已经有 OpenAI 兼容 `/v1`——**这些 UI 直接填 Base URL 就能用**，不需要我们的 15 个页签。

### 3.3 桌宠/陪伴——**别和它们比美术/语音**

| 项目 | 强项 | License / Stars |
|---|---|---|
| [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber) | Live2D、透明桌宠、语音打断、多 ASR/TTS、视觉 | MIT / 14.5k |
| [AIRI](https://github.com/moeru-ai/airi) | Web/桌面/移动、Live2D/VRM、实时语音、游戏 | MIT / 50.9k |
| [Miru](https://github.com/kiyotakali/Miru) | 桌宠 + 长期记忆 + 主动陪伴 + 多设备 | Apache-2.0 / 188 |

我们的 Tk 桌宠在“形象/语音/交互打磨”上落后一个量级；优势只在“记忆注入 + 人格底线 + 本地 SQLite”。

### 3.4 记忆层——**别重写，能借就借**

| 项目 | 可借的 | License / Stars |
|---|---|---|
| [mem0](https://github.com/mem0ai/mem0) | ADD-only、图记忆、混合检索 | Apache-2.0 / 68.1k |
| [Letta](https://github.com/letta-ai/letta) | memory blocks、自编辑、状态代理 | Apache-2.0 / 25.3k |
| [Graphiti](https://github.com/getzep/graphiti) | 双时态、episode 溯源、多跳 | Apache-2.0 / 32.4k |
| [Cognee](https://github.com/topoteretes/cognee) | 图+向量记忆流水线 | Apache-2.0 / 32.9k |
| [MemoryOS](https://github.com/BAI-LAB/MemoryOS) | 短/中/长三段式 + 热度淘汰 | Apache-2.0 / 1.6k |
| [Khoj](https://github.com/khoj-ai/khoj) | 个人第二大脑、文档/网页接入 | AGPL-3.0 / 37.9k |

## 4. 三个可选产品形态（选一个，不要全做）

### A. “大肥鱼住在 QQ 群” — 最像产品
- 前端：AstrBot 或 LangBot（已有 QQ、WebUI、插件、限流、重连）。
- AIJiYi：只做记忆/人格 provider（OpenAI 兼容或 HTTP 插件）。
- 需要补：群聊多人记忆隔离、@ 回复、图片/语音、主动搭话。
- **代价**：依赖 AGPL（AstrBot）或 Apache（LangBot）；自己的控制台退居后台。

### B. “桌面宠物记得你” — 最有情感
- 前端：Open-LLM-VTuber / AIRI（Live2D + 语音 + 打断）。
- AIJiYi：记忆 + 人格 + 主动消息 backend。
- 需要补：把记忆注入接进它们的 prompt 管线（可能要写适配器）。
- **代价**：集成成本高；但美术/语音直接到位。

### C. “个人记忆大脑” — 最可复用
- 前端：Open WebUI / Chatbox / IDE，填 `http://127.0.0.1:8787/v1`。
- AIJiYi：只做 memory service（OpenAI 兼容 + MCP + 管理 API）。
- 需要补：MCP server、记忆管理、评测。
- **代价**：没有“宠物”的情感入口；但用户最多。

**我的建议**：如果目标是“有人真的用”，选 **A**（QQ 是入口）；如果目标是“你自己爽”，选 **B**；如果目标是“开源可复用”，选 **C**。不要同时做 A+B+C——那就是现在的 15 页签。

## 5. 该砍的（Kill list）

1. **控制台工作区/终端**：重复 VS Code，安全面大，用户为零。隐藏或删。
2. **控制台 15 页签 → 4 个**：状态、对话调试、记忆、错误。其余降级为 API/CLI。
3. **控制台里的桌宠**：和桌面桌宠重复。
4. **记忆星图 ECharts**：演示价值 > 日常价值，改成“记忆表 + 搜索”。
5. **语音 profile UI**：先把 SAPI 换成 Edge/Piper，再谈定制页面。
6. **自写 QQ 框架**：用 AstrBot/LangBot/NoneBot2，自己只写 provider。

## 6. 该留的（Keep list）

1. 记忆内核（多平台单表、100ms 召回、软注入、ADD-only）。
2. OpenAI 兼容 `/v1`（让所有现有 UI 接进来）。
3. 桌宠的“人格底线 + 记忆 + 主动消息”三件套。
4. 一个薄 QQ 适配器/插件（不是框架）。
5. 评测：记忆命中率、注入是否被模型使用、用户是否感到“被记住”。

## 7. 一周“有用性实验”（比再写 10 个页面有价值）

1. 选 **一个真实 QQ 群**（3-5 个朋友），跑 AstrBot/NoneBot + AIJiYi 记忆。
2. 每天只做三件事：@ 回复、记住一个新事实、第二天主动提一次。
3. 记录 20 次对话：多少次它“记得”？多少次答非所问？用户有没有说“你居然记得”？
4. 声音换成 Edge/Piper，做 A/B：SAPI vs 新音色，问朋友哪个愿意继续听。
5. 一周后决定：继续 A/B/C 哪条；砍掉没被使用的页面。

**衡量标准不是 282 个测试，而是：**
- 用户第二次回来找它了吗？
- 它提到的记忆，用户觉得“对/暖”还是“尬/错”？
- 朋友愿意把它拉进群吗？

## 8. 对自己的批评

我一直在优化“可演示、可测试、功能多”，不是“人每天会用”。
控制台是给我调试的，不是给用户用的；工作区是给开发者看的，不是给陪伴产品用的。
真正缺的不是第 16 个页签，而是：**一个人类本来就在的入口（QQ/桌面）+ 一次“它记得我”的瞬间 + 一个不尴尬的声音。**
