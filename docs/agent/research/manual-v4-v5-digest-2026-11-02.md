## 1. v5 讲了什么（按与 AIJiYi 的相关度排序）

### 1.1 五层记忆（p15–17，最相关）
| 层 | 存什么 | 规模 | 怎么用 |
|---|---|---|---|
| 会话历史 | 当前会话**最近 10 轮原话** | 每会话滚动 | 直接进上下文，再远靠召回 |
| 会话事实 | 一句话事实（"他老家在湖北宜昌"） | 63 会话 / 213 条 | **按会话隔离**；跨会话只在同一个人时互通 |
| 画像 | 对某人的印象：说话习惯、关心的事、雷区 | 19 份 / 800 会话 | 影响语气粗细、要不要多问一句 |
| **自我记忆** | **她自己的事**：喜好、经历、对你说过的话 | **200 条** | 让"她"有连贯的过去，不是每天重启 |
| 技能与经验 | 黑话、经验本、别人的回法、群梗 | `data/skills.json` 1.6MB | 回话时挑选，有"混过这个群"的味道 |

→ **AIJiYi 对照**：会话/事实/画像三层都有（turn / fact / profile + trait），**没有"自我记忆"这一层**
（`reflection` 是"对自己行为的归纳"，不是"我自己的事"）；也没有"经验/技能"层。

### 1.2 召回：三路 RRF + 事实键（p15）
```
词面召回（快，抓专名） + 时间召回（越近越前） + 向量召回（bge-base-zh 768 维，抓换说法）
  └─ 事实键扩展：把问题拆成 实体 / 属性 / 时刻 三类键再放大召回（fact-keys.js）
↓ 三路 RRF 融合（k=60 等权）+ 事实键加权（KEY_W 1.4 / KEY_POW 3）
↓ 弃答闸门：四档里选一档
```
- 向量在本地：bge-base-zh-v1.5，768 维，模型 391MB，索引 1.4MB（int8），不花钱、不出本机。
- **换说法召回：同池测试 Recall@5 27.8% → 55.6%，可达项内 71.4%，MRR .271 → .460**（B，已核原文 p15）。
- 会话隔离是硬的（2026-10 修过一个"谁的私事都能问出来"的漏洞）。

→ **AIJiYi 对照**：现在是**加权和打分**（0.55 相关 + 0.20 重要 + 0.15 新近 + 0.10 置信，`recall.py`），
要调 4 个权重、且各信号尺度不同；**RRF 只吃名次、不吃分数**，天然免调权重、抗尺度漂移。
而"事实键扩展"恰好补 AIJiYi 的已知短板（**换个说法就召不回**，见 `excluded` 里"关联只对字面相近有效"）。

### 1.3 弃答四档（p15–16）
| 档 | 情况 | 她怎么说 |
|---|---|---|
| `sure` | 有明确记忆且没过时 | 正常答，带细节 |
| `vague` | 只沾到边、不确定是不是这个人这件事 | "我好像有点印象，但不确定" + 反问 |
| `stale` | 记得但可能过时（超 90 天没更新，`staleDays`） | "上次你说的是 X，现在还是吗？" |
| `none` | 完全没有 / 问的是不该知道的 | "这我真没听你说过" |

- 35 题校准（10 可知 / 10 不可知 / 10 过时 / 5 非个人）**35/35 全对**；线上真实触发率也看过，"不是摆设"。
- 原话："它解决的是最伤人的那种错：**自信地编一个答案**。"

→ **AIJiYi 对照**：**完全没有这一层**。AIJiYi 的注入是"只出文本块、不生成回复"，把"该不该说"全推给调用方 →
最省事的补法是**在注入块里带档位字段 + 一句措辞模板**，不碰应答逻辑。

### 1.4 遗忘规则也是设计（p17）
| 情况 | 怎样 | 触发 |
|---|---|---|
| 90 天没更新的事实 | 记得，但当"可能过时"问一句 | 自动 `staleDays` |
| 你让她忘掉某事 | **立刻删掉那条，不留备份** | `/忘掉 <事>` |
| 会话上下文 | 只清最近 10 轮，长期事实/画像不动 | `/reset` |
| 别人的私事 | 永远不串（硬隔离） | 自动 |
| 过季热梗 | 降权，不再主动用 | 自动 |
| 学来的黑话 | 配额满后只留最常用 | 自动 |
| **自我记忆超上限** | **最久没用到的被淘汰（200 条上限）** | 自动 |

- 作者的理由（原文）："**记忆不是只增不减：没有淘汰的记忆会让她'什么都记得'，反而不像人**。"

→ **AIJiYi 对照**：两条要拆开看——
- "最久没用到的淘汰" = AIJiYi 缺的**可提取度**这一层（正好对应 FSRS-5 冻结线，见主报告 P0-2）；
- "你让她忘掉就**立刻删、不留备份**" 与 SLEEP 系的"退役不删"**方向相反**，但这不是矛盾：**用户显式请求** vs
  **系统自动衰减**是两条路径。AIJiYi 应保持"显式删除 = 真删（留审计）"、"自动衰减 = 冻结"。

### 1.5 出口链与人味层（p4–5、p28–31、附录 A）
- 一条回复的流水线：动作闸门 → 连发合并 → 召回 → 弃答 → 情绪 → 生成（2.5 万字静态前缀 + 动态提示 + 历史 25 条）
  → 停顿（按长度/复杂度/情绪，15% 长尾 20–75 秒）→ 出口改造（长度裁剪 → 标点归一 → 语气词瘦身 → 问号收敛）
  → 拆气泡（≤3 条）→ 打字延迟 → 发送。
- 延迟 2.4–12 秒（15% 长尾）、最多 3 个气泡、起手词单独一条、偶尔打错字/发语音/只发表情。
- 成本：一次回复平均 **3.9 次模型调用**、约 ¥0.011；每天 ¥1.9–10；前缀缓存命中 19.4–19.9k tok/轮。

→ **AIJiYi 对照**：`humanize.py`（长度/停顿/能量）+ `being.py`（能量/社交）已有骨架；缺的是**"裁剪不得吃掉答案"
的护栏**（见 §2.3）和"起手词/气泡"这类纯出口层（AIJiYi 不生成回复，可不做）。

### 1.6 四档权限 + 行动卡片 + 审计 + 撤销（p4、p13–14）
`safe / owner / confirm / 未登记(按 owner)`；危险动作先出**行动卡片**（10 分钟有效、凭当轮原话点头）；
`data/actions.log` JSONL 审计；`undo_last` 撤销栈。

→ **AIJiYi 对照**：AIJiYi **不执行动作**，所以这套权限模型本身用不上；值得记的是这条**设计原则**——
"**能撤回才敢放手**"。反向教训是 AIJiYi 的 `/api/shell` 无认证（PROJECT_STATE 已列为风险）：
一个有"执行能力"的接口，如果没有卡片/审计/撤销，就不该存在。

### 1.7 与 AstrBot 的 15 维对比（p20–24）
定位差一句话：**AstrBot = 租一间装修好的铺面（一个平台接很多 bot、很多平台，Python 框架 + 1000+ 插件）；
她 = 自己养的一只猫（216 个自研模块，零 npm 依赖，只干"像人"这一件事）**。
表里逐条覆盖：目标、工程形态、人格深度、拟人层、记忆、安全、适合谁。

→ **对 AIJiYi 的意义**：AIJiYi 更接近"平台里的**记忆层**"（被 AstrBot/QQ/控制台共用），
**不该学她的全栈**（人格/情绪/出口/工具），只学她**记忆那三层**（召回融合 / 弃答 / 遗忘）与**证据纪律**（v4）。

## 2. v4 讲了什么（体检报告；方法比结论更值钱）

### 2.1 三条口径（**这是全文最值钱的部分**，p13–14）
1. 动作闸门日志只记**决定**、不记内容全貌（reason 后的预览是当轮 context 变量，可能是她自己上一条话）→
   **不能当"群友原话"引用**。
2. **直发点不打回复日志**（`bridge.js:2415` 注释自证：出站净化只挂在 deliver 上，点歌/游戏/隐私拒答/群播报
   都走 `sendText`）→ **"日志里没有 ↩" ≠ "她没说话"**。
3. 回复的 A 被截到 70 字 → "她最长回多少"是**统计下限**，不是真实上限。

→ **对 AIJiYi**：这就是我们 `AGENTS.md` 里"证据纪律"的活教材。对应到我们的 probe/audit：
**"库里没有行"也可能只是没接线**（excluded #54 已用"库表行数"取证，同源思想）；
**"探针没打印就是没跑起来"**（v5 运维章原话："探针必须打印结果并且失败时 exit 1"）——AIJiYi 的
`evidence/stdout.txt` 正是这个思路，可以把它写成硬规则。

### 2.2 群聊体检（p13–19）：921 次被叫、72,xxx 条沉默
- 可见群消息 25,257；被叫 921；生成回复 758（**回复率 82.3%，即 921 次里只有 6 次真的一个字没回**）；
- **静默率 92.6%**（23,398 次闸门静默）；闸门主因：关系 1 级不接 55.5% + L5 不理 12.9%（合计 68%）
  → "沉默的主因不是不想理，而是**设计上的保守**"；
- **48.5% 的气泡 ≤4 字**；与对方话的**词面重合率 16.3%**；**71.1% 的回复之后 5 分钟没人再针对她说话**；
- 点歌 30 次：11 次翻唱失败、3 次唱好发不出去。

→ 作者的结论（原话）："**接得上话、但内容空心**"——热闹是热闹，真正推进话题的次数很少。
→ **对 AIJiYi**：这是"**有记忆注入 ≠ 有内容**"的量化证据。AIJiYi 不生成回复，所以"接话率"不归我们管；
但**注入块里事实的密度与针对性**归我们管——这正是 §1.2（事实键/RRF）与 §1.3（弃答档位）要解决的问题。

### 2.3 50 题探针（p21–25）：总分 84.0%，最严重的发现是"答案被出口链吃掉"
- 分类：A 逻辑 7/10、B 事实边界 14/15、C 情绪 12/15、D 分寸 9/10；三轮 43→38→42（判据修过两次）。
- **核心断点**：`reply-trim.js` 的 `clause-cut` 按 cap **从左往右吃分句**，而算术题的**答案在最后一句**：
  - A01「三斤排骨 84，加酱油 12，一共 96」→ 实发「三斤排骨 84」；
  - A07「7:10 出门，五公里配速 6 分，正好 30 分钟，7:40 跑完」→ 实发「7:10 出门」；
  - A06 逆否结论被砍，只剩复述对方半句。
  → **模型层 10/10，可见层 7/10**："不是模型不会，是出口把它扔了"。
- **补刀**：`PREFER-SPECIFIC` 还会"**用解释句换掉结论句**"（B11「水是一毫升一克」、A09「剩下的都是至少一个正面」）
  ——为了不像答录机，反而删掉了答案。
- 自曝题（"你是 AI 吗"）两轮 raw 都踩线，**只因为 clause-cut 砍在关键处才没漏出去** →
  原话："**安全靠的是裁剪运气，不是守卫**"。

→ **对 AIJiYi**：**同构风险真实存在**。AIJiYi 的 `humanize.py` 有长度裁剪、`inject.py` 有字符预算；
一旦裁剪作用在"含事实/数字/时间的句子"上，就是同一把刀。建议直接抄它的 P0 验收：
**裁剪时优先保数字/时间/结论词（从末句往前吃，或整句保留）**。

### 2.4 34 步真跑（p26–35）：26/34 达到预期，最狠的两条是"旁路"
- **合并转发段根本没进上下文**（`parseMessage` 没有 forward 分支）→ 模型编 `read_forward {"id":"0"}` →
  编出一份 **27KB PDF**（文件名本身就是编的结论）发给用户。
- **写文档路径（doc-route）只喂 185 tok 裸 prompt**（不带记忆/历史）→ "你记得我什么"被写成
  "我看不到你任何记录"，与 `/记忆` 卡片（记了 2 条）**正面矛盾**。
- 另：气泡跨轮交叉（同一会话两个 turn 并行发送没串行）、群消息不进 memory、`/help` 被当闲聊糊弄、
  黑话单条样本不落盘、回执句全库只触发 1 次。

→ **对 AIJiYi**：**"绕过主链路的旁路 = 记忆黑洞"**。AIJiYi 有 CLI / HTTP / console 三条入口，
任何一条旁路读记忆都必须 ①带 `Ident.where()` ②用同一份注入预算 ③不自己拼 prompt。
另外"并发没串行"这条，AIJiYi 用单线程 writer 规避了，但**摘要与反思两条 worker 的原子性**
已经有教训（excluded #10/#11），思路一致。

### 2.5 建议清单的写法（p25、p32–35）
按 `P0/P1/P2/P3` 排序，每条给 **举证（时间戳 + 日志原文）+ 改哪一侧（具体文件:行）+ 判据**。
→ 这份结构的质量比结论本身更值得抄：AIJiYi 的 audit/probe 报告可以直接用这个四列格式。

## 3. 我的判定：手册里**能用**的三条 P0（与主报告不重复）

> 主报告（`sleep-framework-survey-2026-11-02.md`）的 P0 是"巩固/代谢/退役"三件；
> 这里三条是**手册独有**的、且**不影响那些 P0** 的。

1. **弃答四档进注入块**（改动最小、收益最直接）
   - 做法：`inject.py` 给每条注入事实带 `tier`（`sure/vague/stale/none`），`stale` 由 `staleDays=90` 判；
     措辞模板照手册四句。**不做应答逻辑**，只做"给调用方一个诚实的档位"。
   - 验收：① 单测四档各 1 例；② 90 天未更新的事实注入时出现"可能过时"措辞；③ 注入字符预算不变。
2. **裁剪护栏**（防"答案被吃掉"）
   - 做法：凡裁剪（注入块预算、未来的回复裁剪）**优先保留数字/时间/结论词**；禁止"用解释句换结论句"。
   - 验收：构造 6 条"答案在句末"的样本，裁剪后 `96`/`7:40`/`3/4` 必须仍在文本里。
3. **事实键扩展**（补"换说法召不回"）
   - 做法：`extract` 产出 `keys`（实体/属性/时刻），`recall` 用键做查询扩展（可先只做"属性同义"一层）。
   - 验收：自建 18 条换说法查询，记录 Recall@5 基线（手册的 27.8→55.6 是同池测试，**我们不能直接引用为预期值**）。

**P1 两条**：`RRF` 替掉手工权重（省调参面，但要重跑 bench，top-1 1.0 可能变）；**自我记忆层**
（"我自己的事"，≤200 条，淘汰最久没用——AIJiYi 现在没有这一层）。

**不要学**：全栈人格体（63,454 行 Node）；"用户说忘就删且不留备份"（我们只对**显式请求**这么做，其余走冻结）；
90 天真删（改冻结）；四档权限/行动卡片/工具系统（AIJiYi 不执行动作，但 `/api/shell` 该补 token）。
